# 0.2.3 内存优化与测量

日期：2026-10-12。Windows x64，3440×1440、100% 缩放，NVIDIA GeForce RTX 5070 Ti。

## 实测结果

两版均为同一台电脑的 release 构建，走相同流程：启动待机，连续三轮整屏截图、四种强度的像素马赛克和带标注导出，每轮结束后等待五秒再测待机。旧版为加入同一测量入口的 0.2.2，新版为 0.2.3。

以下单位为 MiB（1,048,576 字节）。工作集是当时驻留的内存，私有提交是进程申请的私有内存；同时列出这两项以验证实际释放。未调用工作集裁剪或强制换页接口。

| 阶段 | 旧版工作集 | 新版工作集 | 旧版私有提交 | 新版私有提交 |
|---|---:|---:|---:|---:|
| 启动待机 | 147.1 | 12.9 | 185.3 | 2.3 |
| 第三次截图打开 | 197.7 | 163.9 | 297.6 | 232.2 |
| 第三次截图结束后待机 | 179.2 | 27.8 | 240.0 | 8.6 |
| 全流程累计峰值 | 254.5 | 223.4 | 316.6 | 253.0 |

启动工作集降低约 **91%**，截图后待机降低约 **85%**。三轮结束后的新版待机工作集分别为 27.7、27.8、27.8 MiB，窗口和图形设备均已释放。

数据：[旧版 CSV](memory-before.csv)、[新版 CSV](memory-after.csv)。这些数值来自一次完整运行，包含中文字体与驱动的实际分配；其他屏幕尺寸、驱动、贴图数量和后台负载会改变结果。此处未测量独显的专用显存。

## 实现变化

1. **按需初始化。** 启动仅建立托盘和全局热键，首次截图或贴图才加载窗口、字体及图形设备。
2. **及时结束会话。** 确认/取消后隐藏窗口、等待桌面合成，再销毁交换链、渲染器、底图、马赛克缓存、图集、编辑历史和输入上下文。样式和 HEX/RGB 偏好仍保留。
3. **释放空闲设备。** 无截图、无贴图时，保留图形设备三秒供快速再次截图复用，之后等待队列完成并释放。贴图存在时保留设备，最后一张贴图关闭后也会释放。
4. **减少驱动初始化。** Windows 优先只建立 DX12 后端，初始化失败则尝试 Vulkan。避免启动时同时建立多套后端。本机使用 DX12 的释放后待机明显低于默认多后端/Vulkan 路径。
5. **缩小像素马赛克纹理。** 一个块仅保存一个平均像素，最近邻采样还原整块；末尾不足一块的区域仍按原始像素平均，UV 按补齐后的网格计算。在本屏幕上，四种强度 8/16/24/32 的缓存从约 75.6 MiB 像素数据缩到 0.42 MiB。模糊效果仍按原始分辨率处理。
6. **复用与借用。** 标注导出复用预览的底图 GPU 纹理，直接计算裁剪范围；多上下文共享中文字体的弱缓存；二维码灰度转换、PNG 保存和贴图复制取消额外的 RGBA 拷贝。

## 操作上的取舍

设备释放后的下一次截图需要重新初始化。此轮三次截图从触发到隐藏首帧准备完成分别用时 **418 / 330 / 323 ms**；旧版已常驻设备的对应时间为 105 / 116 / 116 ms。选择这项策略是为了降低长时间待机占用。

准备完整首帧后才显示窗口的顺序保留。原生验收检查了三次释放设备后的首个可见帧、确认后剪贴板读回，以及冷启动贴图、贴图期间截图、最后一张贴图关闭后的设备释放。

## 复测

```powershell
. ./scripts/env.ps1
cargo build --release -p snipaste-app
./scripts/profile-memory.ps1
```

测试会暂时显示截图窗口，执行三轮操作并自动退出，不写剪贴板。报告默认保存到 `target/memory-after/memory.csv` 和 `run.log`。普通运行未设置测量环境变量时，不执行这些操作。

验证结果：139 个普通测试通过，格式检查及 clippy 零告警，Windows 原生截图、马赛克、局部擦除、颜色取值、二维码、图片/文本剪贴板和资源生命周期验收通过。
